# A800 部署 / A800 deployment

单卡 A800 80G 接管预训练;GB10 解放出来跑对齐轮。预期吞吐 9-15k tok/s
(GB10 实测 1.9k 的 5-8 倍),一个 epoch(2.14B token)约 1.6-2.7 天。

## 1. 上传(从 box 发起,合计约 47G;不接续则 47G)

```bash
S=user@a800-server            # 换成实际地址
ssh $S 'mkdir -p ~/dol/{repo,data,runs,ckpt}'

# 代码(不含 .git,~14M)
cd ~/projects/LLM/DoL-OCR && git archive HEAD | ssh $S 'tar -x -C ~/dol/repo'

# 数据:packed shards(15 个,单个约 3G)+ held-out;box 上实测 47G
ssh spark1 'tar -C ~/dolocr -cf - pretrain_data' | ssh $S 'tar -x -C ~/dol/data --strip-components=1'

# 断点(可选:保留已训 0.26B token 进度;box 上 11G)
# 注意 torch 版本:box 存档用 torch 2.10+cu130,镜像是 2.5.1+cu124。
# torch.load 通常向下兼容,但不保证逐位可复现;若加载报错,直接删掉
# ~/dol/ckpt 从零开跑——step 4068 在 A800 上约 7 小时即可补回,不值得为
# 接续冒版本险。想稳妥接续就把镜像 torch 版本改成与 box 一致再传断点。
ssh spark1 'tar -C ~/dolocr/runs/mn_pretrain_v1 -cf - step_00004068' | ssh $S 'tar -x -C ~/dol/ckpt'
```

box 与服务器能直连时,把两条 `ssh spark1 | ssh $S` 改成 box 上直接 `scp` 更快。

## 2. 构建镜像(服务器上)

```bash
cd ~/dol/repo && docker build -t dol-pretrain:cu124 docker/
# 国内服务器 docker hub 不通时:先配 registry mirror,或本地
# docker build + docker save | ssh $S docker load
```

驱动要求:nvidia-driver >= 525(cu12.4),`nvidia-smi` 正常即可;需要
nvidia-container-toolkit(`docker run --gpus all` 可用)。

## 3. 吞吐阶梯(先测再跑,QA 纪律)

```bash
cd ~/dol/repo && bash docker/a800_run.sh probe
```

三个配置各跑 40 步:micro16/无检查点 → micro8/无检查点 → micro8/有检查点。
A800 是 80G 专用显存(不是 GB10 的统一内存),上限要实测。拿幸存配置里
tok/s 最高的进入下一步。

## 4. 长跑

```bash
MICRO=16 ACCUM=2 CKPT=off nohup bash docker/a800_run.sh full > ~/dol/full.log 2>&1 &
tail -f ~/dol/runs/mn_pretrain_a800.log | grep step=
```

- `~/dol/ckpt` 里有 box 的 step_00004000 时自动接续(保留 0.26B token 进度),
  否则从零开跑。
- 输出与 checkpoint 落在宿主机 `~/dol/runs`(volume),容器可随意重启。
- 停止:`docker ps` 找容器 → `docker exec <id> python3 -m scripts.rdt_monitor
  control stop --run /work/runs/mn_pretrain_a800`(优雅存档退出)。

## 5. 产物回传

```bash
# 每天或跑完:最新 checkpoint 回 box(对齐轮在 GB10 上用它)
rsync -a --delete $S:dol/runs/mn_pretrain_a800/latest/ ~/dolocr/runs/a800_latest/
```

## 硬盘 / Disk budget（服务器上,实测推算）

| 项 | 大小 |
|---|---|
| Docker 镜像(pytorch devel 基底 + 依赖) | ~11G |
| 数据 pretrain_data(15 shards + eval) | 47G |
| 接续断点(可选) | 11G |
| 训练产物 runs(keep-last-n=4,单个 11G) | ~44G |
| 代码 + 系统余量 | ~5G |
| **合计** | **约 120G 起** |

系统盘至少留 **120G 空闲**,宽裕起见 **200G+**。多数 A800 租用机系统盘
200G–1T,通常够;若挂了独立数据盘,把 `~/dol` 指到数据盘更稳妥。

## 分工 / Division of labor

- **A800**:预训练长跑(本文档)。
- **GB10(box)**:停掉本机预训练后,专跑对齐轮
  `nohup bash scripts/swap_to_align.sh ...`(见 RUNBOOK)——用 A800 回传的
  更深底座反复重跑对齐,不再与预训练抢卡。

## 已知差异 / Notes

- torch 2.5.1+cu124(镜像)vs box 的 2.10+cu130:checkpoint 双向可读
  (torch.save 格式稳定);bf16 数值路径一致;RNG 序列跨版本不逐位一致,
  resume 处的数据顺序不受影响(由确定性 fast-forward 保证)。
- A800 不存在 GB10 的 page-cache/CUDA 竞争,evict 不需要;save 卡死模式
  理论上不应复现(专用显存),复现即按 RUNBOOK 同款处置。
